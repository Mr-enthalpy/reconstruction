# D5.1 场景尺度与 PSF 尺度一致性

日期：2026-10-21。场景为训练集中的 `beads`、`cloth`、`feathers`，512×512。参考核为 1024 传感器支撑、1×、unit-sum。

## 1. 比较方法

两条数值路径：

1. **先高分辨率模拟再降采样**：512 场景 × 1024 参考核 → 512 测量 → 按 factor 做块平均到 512/f。
2. **先缩放场景与核再卷积**：场景块平均到 512/f；1024 参考核按 factor 块求和后 unit-sum → 在 512/f 网格上卷积。

两者都使用零边界、中心裁剪、signed shape-only。差异包含场景重采样、核积分、边界和频域截断的综合影响。

## 2. 结果

| factor | 测量相对 L2 | 高频相对 L2 |
|---:|---:|---:|
| 1 | 0.0 | 0.0 |
| 2 | 0.00904 | 0.0625 |
| 4 | 0.02590 | 0.2382 |

factor=1 是同一路径，误差为零。factor=2 的总测量差异约 0.9%，但高频差异约 6.3%；factor=4 的总差异约 2.6%，高频差异约 23.8%。

## 3. 解释

- 总测量在低倍率下仍接近，但高频/局部结构对“场景先缩放还是测量后缩放”敏感。
- 因此不能把 `scene_hw=256` 与 `kernel=64/96/128` 的结果解释为同一物理视场下的严格比较。
- D5.1 pilot 统一使用 512×512 场景；baseline 也在 512 上重跑，避免把场景尺度变化误归因于 PSF 支撑或积分倍率。
- 本结果不证明真实相机分辨率，也不证明 512 场景等价于某个传感器视场；`scene_to_sensor_scale` 仍是未标定假设。
- 若未来采用分块训练，必须先从完整场景生成测量，再提取带 halo 的区域；不能先裁场景再独立做 PSF 卷积。

## 4. 对 D5.1 的影响

- S4/S5 的 192/256 核必须在 512 场景上评估，不能与 256 场景的 64 核结果直接混比。
- 前向截断审计使用“有限核放回共同 1024 传感器坐标”的方式；本文件则量化了场景网格改变本身带来的额外差异。
- 两项误差必须分开报告：PSF 支撑/积分误差 vs 场景重采样误差。
