## 1. 目的与范围

在实验室资源系统（Citespec Resource）的一次真实租用中，用**单张 GPU**完成 D5.2
A6 基线的一次可复现训练。这次运行回答两个问题：

1. 在既定配置下，一次受控的单卡训练能否真实完成，并留下可复现证据？
2. 训练预算对高频恢复的影响有多大？

它**不**回答"高频误差主要由什么造成"，也**不**回答"实测色散 PSF 是否有贡献"。

范围限制（与 D5/D5.1 一致）：

- 21 波段 450–650 nm，512×512 场景，39 train / 9 val；
- measured PSF 仅作 **signed shape-only** 近似，不是标定过的物理模型；
- 不加载冻结测试集，不做分类、不做 RGB 前端、不做压缩、不做联合优化；
- 不涉及硬件采集，不修改 `optic_system`，不修改 Meta pin。

## 3. 配置

`experiments/d5_2/configs/a6_formal.json`，未改动：

- 模型 A（CNN-PGD），6 stages，width 64，depth 4，**98,139 参数**；
- batch 1，100 步/epoch，目标 300 epoch（30,000 步），`patience=40`，`eval_every=5`；
- AdamW，lr 2e-4，cosine 退火到 1e-5，weight decay 1e-5，grad clip 1.0；
- 训练噪声 RMS 比例 0.5%，亮度抖动 [0.9, 1.1]；
- 损失：`lambda_grad=0.2`、`lambda_spectral=0.05`、`lambda_data=0.02`；
- 选模：最小验证重建目标；seed 20261021。

实际运行分两段，第二段从第一段 `last.pt` 续训（含 optimizer/scheduler/RNG 状态）：

```bash
python3 -X utf8 experiments/d5/train.py \
  --prepared /workspace/data/prepared512 \
  --output   /workspace/runs/a6_4000 \
  --config   experiments/d5_2/configs/a6_formal.json \
  --device cuda --resume /workspace/runs/a6_4000/last.pt --stop-after 300
```

## 4. 结果

实际完成 **248 epoch / 24,800 步**。结束原因是配置自带的 `patience=40`：epoch 208 取得
最小验证损失后，连续 40 个 epoch 没有改善，**不是时限、也不是步数上限**。因为这条规则
在训练前就已确定，这属于按既定规则结束，而不是意外中断。早停时 lr 仍有 2.4e-5，说明该
配置在这个预算下还没"跑穿"，但这不改变本次结果的有效性。

### 4.3 选模规则与指标间的权衡

选模规则在训练前确定，全程只有一条：**最小验证重建目标**。据此选中的唯一模型是
epoch 208（val loss 0.012924），本报告所有"模型性能"都指这一个模型。

两点必须写清楚：

- **不做跨 epoch 拼指标。** epoch 240 的高频相对误差 0.7513 低于 epoch 208 的 0.7619，
  但它的整体验证损失 0.013021 更差。这是指标之间的权衡，不是可替换的候选模型；
  从不同 epoch 各取最好的一项拼成一组数字，会系统性高估性能。
- **本次运行有记录缺陷，但复算可追溯。** 该 run 用的是旧代码，`eval_every=5`，而 best
  epoch 208 不是 5 的倍数，所以 `history.json` 的 208 行没有 metrics，最优模型指标只能
  由 `validation.json` 复算（见 4.2）。复算结果与 checkpoint 一致，但它本应在训练时
  直接落盘。记录方式已经改正：验证损失每刷新一次最佳值，就立刻计算并写入完整指标，
  同时把选模规则、指标和 PSF 来源一起写进 checkpoint 与 `validation.json`，并在收尾时
  与重算结果比对（见 2026-10-28 S1/S3 报告）。

## 5. 结论

1. **训练真实完成，并按既定规则结束。** 实际执行 248 epoch / 24,800 步。epoch 208 取得
   最小验证损失后，连续 40 个 epoch 没有改善，于 epoch 248 触发配置自带的 `patience=40`。
   早停规则是训练前确定的，因此这是一次**按规则正常结束的早停版 A6 正式验证基线**，
   不是意外中断，也不需要用补齐剩余 5,200 步来"救回"。若继续训练，应当是有明确科学
   目的的新实验，而不是机械把步数补满。
2. **充分训练显著缓解了高频恢复不足，尚不能确定剩余误差由哪些因素主导。** 4,000 步 →
   24,800 步：HF relative L2 0.942 → 0.762（相对下降约 19%），同期 PSNR +0.95 dB、
   SSIM +0.020、SAM −1.10°、cube relative L2 0.275 → 0.249；16k → 24.8k 仍有
   0.785 → 0.762 的下降，而 500 → 4,000 步只从 0.970 降到 0.942。所以可以确定的是：
   **训练预算不足是早期高频误差偏大的重要原因**，用 4,000 步短跑下"高频无法恢复"的
   结论会明显偏悲观。不能确定的是它的反面——最佳模型 HF 仍有 0.762，距零误差还远，
   结构、先验容量、逆问题病态性都**不能**据此排除。
3. **整体重建质量与高频恢复并不同步。** epoch 240 的 HF（0.7513）优于 epoch 208
   （0.7619），但整体验证损失更差（0.013021 vs 0.012924）。这说明不同指标之间存在
   权衡；因此必须保持统一的选模规则，并报告每个已记录 epoch 的 HF / SAM / 光谱轨迹
   （4.1 与 `metrics_trajectory.csv`），而不是事后挑选各指标最好的不同 checkpoint。
4. **实测色散 PSF 对重建的贡献尚未证明。** 本报告只有 Chromatic（实测色散）一组。
   它说明 CNN-PGD 能从当前模拟观测中恢复相当好的高光谱图像，但不能区分恢复所用的
   信息来自光学编码，还是来自数据集与网络先验。判据是 Achromatic 匹配训练
   （同数据、同预算、同 seed、只换核）在同一验证集上的**逐场景**对照；在那一组完成前，
   不应训练更大的网络来"证明"PSF 有用，也不应下"PSF 有贡献"或"没有贡献"的结论。
5. **单点指标有噪声，选模不能按 epoch 挑数。** SAM 在 epoch 100–120 反弹到 11.078 后
   才继续下降；选模必须依据验证损失或固定评测点，不能凭单个 epoch 的 PSNR / SAM 判断。

## 6. 明确不支持的结论

- **不是** 300 epoch / 30,000 步的满额运行：它在 `patience=40` 规则下于 248 正常结束，
  是已完成的早停版基线；不需要机械补齐步数。
- **不是** PSF 贡献的证据：只有 Chromatic 单臂，缺少 Achromatic 匹配对照。
- **不是** 冻结测试集结果：全程只用 train/val，`test.npz` 未加载，不能据此宣称泛化性能。
- **不是** 与 A-large、C6-SFAT 的对照结论：本次只跑了 A6 单模型单 seed。
- **不是** 硬件或光学验证：PSF 仍是 signed shape-only 近似，未经辐射度/Bayer/视场标定。
- **不是** 设备无关结论：本次在 RTX 3090 上运行；与 amax 的 4090 数值不可直接等同。
- 不涉及分类、RGB 前端、压缩、联合优化、PSF 掩模优化。

## 9. 后续

按当前判断，优先级是：

1. **Chromatic vs Achromatic 匹配对照（最高）**：同数据、同预算、同 seed，只换核，
   在同一验证集上逐场景比较。这是"实测 PSF 是否有贡献"的唯一判据；在它完成前不训练
   更大的网络。
2. **记录方式修复（已在本次运行之后落地）**：验证损失刷新最佳值时立即计算并写入完整
   指标；checkpoint 记录核的数组摘要与物理 buffer 摘要，避免评估或续训时静默换核。
3. **剩余误差归因**（结构 / 先验容量 / 逆问题病态性）：需要单独设计的实验，不能靠继续
   加预算。
4. S2 A-large 与容量匹配 C6-SFAT。
5. 以上冻结后，再一次性评测冻结测试集。

本次运行的价值是把"训练预算不足"这一项从 D5 的高频失败解释中**部分排除**——它解释了
早期误差偏大的一部分，但不解释剩余的 0.762——并为后续对照提供同配置、可复现的单卡基线。
